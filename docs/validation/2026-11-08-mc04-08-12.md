The explicit `MONTCLIP_TEST_ENGINE` test runs the real worker against the separate upstream source in disposable data directories. It does not alter the pin, install a plugin, or prove an installed package works.

## Follow-up baseline comparison

Same machine, same test command: plugin baseline `2732eae4c30b7fe3bfc3ca59a648d0c676cd2f4c` and candidate both have 7 passing / 1 failing ASR-card tests with either Chrome or Edge. The browser exits 0 with empty DOM stdout; even a minimal synthetic HTML probe has empty output. This establishes a baseline environment failure, not a card-layout diagnosis. No #8 code was changed.

Engine baseline `2d1c566f76e2187d2519b0a94a8156f64647ce80` and candidate both have 3 passing / 4 failing faststart-ownership tests in the original environment, and 7/7 passing with the existing FFmpeg pair. The tests mock encoding but still call the real FFmpeg availability gate; unavailable FFmpeg causes an early return before the target assertions.

The former cross-project flake was reproduced with a concrete Windows `EPERM` during receipt replacement while the test read that receipt. Upstream #240 now covers transient reader contention, permanent receipt-write failure, a crash between the mutation and final receipt, rejected scope queries, and captured audio tracks at the actual browser job entry. Test SSE readiness and server identity are also checked instead of assuming a fixed delay or an unrelated HTTP 200 proves readiness.

The fixed cross-project case passed 30 consecutive runs. The focused existing-FFmpeg run passed 55/57 (2 model-dependent skips), covering the previously missing-FFmpeg failures. The full engine run was 2401 tests: 2379 pass, 7 fail, 15 skip. One failure was introduced by the stricter harness readiness contract: the cleanup stand-in did not announce listening. The stand-in was corrected; readiness plus cleanup then passed 2/2. The remaining full-run failures involve the embedded-assistant observation window (1) and a headless browser exiting before export completion (5); final comparisons are recorded in the PR. The full-run result is not retroactively marked green after targeted corrections.

The existing binaries were only executed via process-local overrides. SHA-256: FFmpeg `393413629e4cd237ab6c18c2e0724fd4d7d4cdd41a94f0bea6c393a1f8768fee`; ffprobe `d6ba076e938628433207a418a24d40e981ba8f43a5bb473a7bd0e5f4c8742fc9`. Machine paths are omitted from public evidence.

Receipt failure remains conservative: the owner can return `TASK_RECEIPT_SAVE_FAILED` while another process still sees the last durable running state until the owner exits. Process-id reuse can also delay recognizing an unavailable owner. Neither case replays the mutation; this is not a claim that every reader immediately knows the uncertain terminal state.

This does not establish that all 80 are necessary. Core ASR/transcript/server APIs differ and `asr-status.js` is absent at the old pin; a backport is not assumed mechanically safe. No pin change or backport was made.
