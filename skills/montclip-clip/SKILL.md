## 0. 先读：两种操作方式

| 方式 | 怎么调 |
|---|---|
| **界面**（桌面版 / 浏览器） | 按本文写的按钮点。中文界面里，**属性面板**的 `Audio / Time`、`Silence`、`Beats`、`Reframe`、`Filter / Color`、`Tracking` 这几节**目前仍显示英文**，本文就照屏幕上的英文写。 |
| **Agent，MontClip MCP** | 直接调 `fablecut_*`，例：`fablecut_songs {mediaIds:[…]}`。长的听写、找歌、高光和字幕整段改动可以带上限等待：`wait_ms`（0–15000 毫秒，默认 6000）只限这次最多等多久，不会把后台任务停掉；回复给 `taskId` 和 `status` / `progress`，之后用同一工具加 `{taskId}` 取回保存的结果，不要连着轮询。改项目的操作带 `idempotency_key`：同一把钥匙加同样参数重试，会拿回原来那次的结果，不会再改一遍；要做另一次新改动就换一把新钥匙。中断的任务标成 `interrupted`，不会自动重放。 |
| **Agent，Cindy 里的 MontClip 插件** | 先调 `montclip_status`，再调 `montclip_open_task_view`（撤销/重做要用到它）。剪辑操作一律用 `call_tool({name:"fablecut_songs", args:{…}})`，参数说明用 `list_tools({category})` 查。插件还有自己的 `montclip_undo` / `montclip_redo` / `montclip_seek {t}` / `montclip_export {preset, range, folder, job, cancel}`；`{job}` 查导出，`{cancel}` 停导出。`fablecut_projects` 由插件转给它的任务命名空间，参数与 main 相同；**只有主播要求切换 / 新建 / 另存项目时**才用 `new` / `open` / `duplicate`。 |

本文写成 `fablecut_xxx {参数}`。在 Cindy 里，把它包进 `call_tool` 就行。

**Cindy 插件长任务与项目切换（#42、#60）**：`fablecut_transcribe` / `fablecut_captions` / `fablecut_songs` / `fablecut_highlights` 由插件提交后，**等多久不占用这个任务的操作队列**——听写等着的这几秒里，`montclip_status`、撤销、切项目这些响应都照常走，不会被听写挡住。回复给 `taskId` 后用同一工具加 `{taskId}` 取回保存的结果，不要连着轮询。`fablecut_projects` 的 `new` / `open` / `duplicate` 也只限主播要求时才做（不是她要求就别动项目）。切换成功后，**这个任务**以后的 `fablecut_get_project`、剪辑、导出都指到新项目；插件回执会明说「This task now uses this project. Re-read it before editing.」，切换后先把项目读一遍再改。开别的任务正在用的项目会被 `PROJECT_TASK_CONFLICT` 拒掉，不能替另一任务夺项目；绑定写失败会先回滚原项目，回滚不成功是 `PROJECT_ROLLBACK_FAILED` 提示停止检查。同一把 `idempotency_key` 重试是取回原回执，**不会把项目再切一遍**。注意已开的**编辑器页签**跟不跟着换，要看界面有没有确认切换（#56 / #2 的追踪还没合并），不要把插件回执说成「编辑器已经切过去」。

**Cindy 插件导出（#9、#22、#24、#55）**：`montclip_export` 开始导出后立刻返回 `job`（**不要跟主播说切去做别的任务导出也不会断**：在 Cindy 里导出是在这个任务的剪辑器标签页里渲染的，切走以后会不会中断还没有核实过；主播问起时如实说「导出要在这个任务的 MontClip 剪辑器页签里做完，请先别关掉它；切走的话我没法保证不会中断。」主人 2026-11-09 定的方向是导出默认放到后台、不占主面板，见 MontClip-Cindy#53，做到之前不能这么承诺，**这个方向做完前也不要对主播提**），用 `montclip_export {job:"…"}` 查、`{cancel:"…"}` 停；同一任务还在导出时再调会返回同一个 `job`，不会重复开。`status:"done"` 只表示文件已经放进所选文件夹；复制失败是 `status:"failed"`、`phase:"copyFailed"`。插件重载后如果无法确认是否交付，会返回 `status:"exported"`、`copied:null`，要去目标文件夹或 MontClip 数据目录的 `exports/` 人工确认。最近 200 个已完成的引擎结果会留在本机，引擎一小时后忘了 `job` 也能查到，卡片可据此继续交付；但重载后的 `exported` 仍不等于已经存进所选文件夹。查询、取消、交付和打开所选文件夹只认发起任务的 session，跨任务返回 `EXPORT_TASK_MISMATCH`。记录彻底没有时返回 `status:"failed"`、`code:"NO_JOB"`，提示「这次导出的记录已失效，查不到了。请先打开导出文件夹，看成片在不在；不在的话，重新导出一次。你的剪辑都还在，没有丢。」卡片给〔打开导出文件夹〕，不再无限〔重试〕。目标盘不支持硬链接时会改为复制，仍不覆盖同名文件。经 `call_tool` 调 `fablecut_export` 也会立刻返回引擎 `job`（插件自动加 `wait:false`），之后用 `fablecut_export {job}` 查；这条直接引擎路径不等于 `montclip_export` 的选文件夹交付。

**Cindy 插件 FFmpeg 报错（#45）**：插件下载或安装自带 FFmpeg 失败时，`montclip_install_ffmpeg` 和进度消息只返回**白名单 code + 固定白话句**（中英两套，JJ 定稿），**不带本机路径、不带 ffmpeg 自己的原始报错**。能出现的 code：`DOWNLOAD_FAILED`、`INSTALL_FAILED`、`DISK_FULL`（含 `ENOSPC` / `EDQUOT` 合并进来）、`CANCELLED`、`UNSUPPORTED_PLATFORM`、`HOST_TOO_OLD`、`SIZE_MISMATCH` / `SHA256_MISMATCH` / `BAD_ARCHIVE`（统称检查失败）。要发回给主播的原始错误走〔复制问题信息〕按钮，已由插件脱敏后给主播复制；Agent 不要替主播把命令行原文贴出来。

**Cindy 插件状态里的「编码 MP4 的 FFmpeg」（#46）**：`montclip_status` 和 `montclip_export` 的回复会**说清楚当前导 MP4 用的是哪一个 FFmpeg**——`bundled`（MontClip 下载的）、`settings`（设置文件里指定的）、`path`（系统 PATH 里找到的）、`env`（启动时指定的）、或本机自带的；查不到就明说「现在查不到是哪个 ffmpeg」。同时给 Agent 一条**措辞约束**（`MP4_PLAIN`，JJ 定稿）：跟主播说这条时**只用大白话、只说到上面这条事实为止**；**不要另外说别的来源**；不要念版本号、环境变量名、文件夹名。编码器名也换成白话（比如 `h264_nvenc` 说成「N 卡的硬件编码器」）。`MP4_PLAIN` 这个名字和版本号可以出现在给 Agent 的说明里，但不要出现在对主播说的话里。

**Cindy 插件中途停止（#20）**：提示定稿为「导出到一半停了，这次没导完。原片没有改动，可以再导一次：点〔重试〕。」这只是失败提示，不把 stopped 当完成；重试后仍要查到 `done` 并做 §5.4。

**桌面助手确认卡（#120）**：需要批准的剪辑步骤，确认卡放在助手消息流里，跟着对应的回复或计划，不再弹出来盖住页面。卡片等着时，后面的步骤不会跑，也不能继续发消息；只会认这张卡自己的按钮，按钮仍是「只批准这次」「这个聊天中都批准」（有这项时）和「不同意」。焦点不会自动落在批准按钮上，按空格不会误批准，Esc 是「不同意」。离开聊天、项目改过，或者来了更新的卡片，等待中的这一步都不会做。

**main 后台任务排队（#132）**：遇到 `JOB_BUSY` 不要乱开重试，先等上一个导出、听写等任务做完；回复里的 `busy` 给出任务号，确实要停时用 `fablecut_export {cancel:"<那个任务号>"}`。编辑窗口每 5 秒报一次心跳；已经隐藏或断开的窗口连续 20 秒没回应，任务以 `EDITOR_STOPPED_ANSWERING` 失败，不会转交无头浏览器再跑一遍。还看得见且保持连接的编辑窗口不会被这条 20 秒规则误杀；无头任务或身份未知窗口的停滞上限仍是 120 秒。把编辑窗口切到前面再试，原片不会因此改动。

**main 的 Cindy 嵌入编辑器（#219、#221、#222）**：`?host=cindy` 时跟随 Cindy 浅色 / 深色主题，隐藏内置助手；内置助手不读密钥、声音数据，也不发 AI 请求，AI 操作直接在 Cindy 自己的对话里说。若仍有内置助手审批请求落到兜底，会立刻拒绝并提示「这一步没有做，什么都没改。在 Cindy 里用 AI，请直接在 Cindy 的对话里说你想做什么。」提示停留 8 秒，鼠标停在上面时不消失。歌词卡仍照常独立询问，不能借嵌入模式跳过主播确认。这批改动已在插件引擎里（引擎锁 `de6640df`）。

**main 的嵌入任务绑定与作用域（#215 E3 / E5a / E5b，合并 PR #249 / #251 / #260；#256 / #258 配套）**：`?host=cindy` 下，一个编辑器的**任务身份绑在它的事件流连接上**，不绑 cookie——同一个 Cindy 页面可以 frame 多个任务的编辑器、共享同一个 cookie。worker 用 `POST /api/embed/ticket {project, session}` 拿一张 60 秒一次性 ticket，父页面把 ticket 放进 frame 首个地址（`?host=cindy&ticket=<票>`）；页面立即把 ticket 从地址里取出，连同自己事件流的 `conn` 一起 `POST /api/embed/claim` 把它**绑到那条 SSE 连接**，从此 ticket 失效。ticket 被复用 / 过期 / 别的引擎发的 / 连接已绑定 / 连接已断开，都回 `403 TASK_TICKET_REFUSED`、什么都不绑。事件流断开重连时，页面用 `postMessage` 找父页面要新 ticket（只接受来自父窗口、父 origin 的 `montclip-host-ticket` 消息）。**导出、范围测量、跟踪、听写等后台任务也都按 `{project, session}` 绑**——开着另一个项目的 editor 时，当前项目任务立即以 `EXPORT_PROJECT_CHANGED` 失败，不会渲染错项目；只有自己任务绑定的连接才能接这个任务的导出。side panel 和它的 editor 走 `BroadcastChannel("montclip-editor:<channel>")` 通信，`<channel>` 是 32 位十六进制的 HMAC-SHA256（key 在引擎启动时生成，重启后所有 channel 都换），面板用 ticket 经 `POST /api/embed/channel` 换自己的 channel。错误文案里的 `ticket=`、`token=`、`channel=` 这些值会被自动脱掉（#255 / #257）。插件 #48 起，这套绑定也在 Cindy 插件里生效：每次放置编辑器或面板都先向 worker 取一张新 ticket，面板用 ticket 换自己的 channel，没有 channel 就不再退回无作用域的 UI 指令。Agent 做跨任务编排时：一个任务的导出不要落到别的任务的编辑器；面板通过插件正常打开（`montclip_open_task_view`），不要自己拼 ticket。**对主播怎么说**：`EXPORT_PROJECT_CHANGED`、`TASK_TICKET_REFUSED` 这些 code，和 ticket、channel、SSE 这些词，都不要念给主播；引擎和界面目前没有这两个 code 的中文白话句（`EXPORT_PROJECT_CHANGED` 只有英文 "The export project changed."），所以不要现编，对主播只说「这次没有导出（或没有打开），原片没动，再试一次」，并说清是哪个项目的任务。专门的白话句由 JJ 另行定稿。

**main 缺 FFmpeg 时的提示（#259，E4）**：main 缺自家捆绑的 ffmpeg / ffprobe 时，报错结尾会带一句**怎么修好**——来自启动方写的环境变量 `MONTCLIP_FFMPEG_REMEDY`。Cindy 插件（`node/worker.cjs`）把它设成英文「In Cindy, install it from the MontClip editor tab's banner, or ask the chat to run montclip_install_ffmpeg.」；Windows 桌面版不设，用缺省的英文「Reinstall MontClip to restore it.」。Agent 看到这条提示时，**把它的意思照实转给主播**；**只针对这一条（缺自家捆绑的 ffmpeg）**，不要另外教主播去网上找一个 ffmpeg 来补。引擎在别的提示里叫主播选 FFmpeg（比如导出要 x264），照引擎的话说。拿到的是英文就转成白话中文：缺省那句说「重装 MontClip 就能恢复。」；插件那句说「点 MontClip 编辑器上方横幅里的〔下载并安装〕就行；也可以跟我说一声，我来帮你装。」（JJ 定稿；按钮名见插件 `ffmpeg-banner.js` 第 41 行）。主播让 AI 来装时，先跟她说清要下载什么（FFmpeg 的 LGPL 版本）、从哪下（GitHub 上 MontClip 的发布页），她同意了再装；聊天里会不会自动先显示下载来源还没核过，不要对主播承诺它一定会显示。

**main 的快速导出可以放到后台（#264）**：main 上从「导出」对话框发起的 Fast（FFmpeg）导出，点〔导出〕后在一个隐藏页面里跑——渲染的是点下去那一刻时间线的**完整拷贝**，之后再怎么剪都不会进这次导出的文件。进度窗可以点〔收起，接着剪〕（或 Esc、点窗外）关上，导出继续做（对主播就说「可以收起进度，接着剪」，不说「后台」）；顶栏的〔导出〕按钮变成「导出中 {pct}%」，点开能看进度或取消；导出队列里也有这一条（带取消）。还没出第一条进度前显示「准备导出…」。完成时如果导出期间时间线又改过，提示会说「这个文件是你 {时间} 点「导出」时的样子，之后的改动不在里面。想带上新改动，请再导出一次。」三种情况不放后台、仍用旧的进度窗：**打开着复合片段**、**导出范围里用了 AI 抠像**，或隐藏页面起不来，提示会说「这次没法一边导出一边剪…导出期间请别关掉 MontClip，等它做完再接着剪。」WebCodecs 和「边播边录」也始终在当前窗口里跑，提示同样要求别关。一次只跑一个后台导出；再点会提示「还有一个导出没做完。等它做完，或者先取消它。」取消会说「导出已取消，没有留下文件。」（半成品会被丢掉）。导出前的逐段声音核对、失败清理等自检流程不变。**Cindy 插件不走这条**：插件的 `montclip_export` 在这个任务的剪辑器标签页里渲染（引擎快照 `de6640df` 还没有 #264），切走标签页后会不会中断没有核实，口径按上面的插件导出段（#55）。

## 1. 团队铁律（每一步都要守）

1. **隐私打码**：连麦的人、观众昵称、礼物栏、榜单行，**全部打码**。镜头推近、拉远的地方（有缩放或位置关键帧，或者做过 Reframe 的镜头），每个打码镜头都要**逐帧**检查，不能只每秒抽一帧（做法见 §5.1）。
2. **找歌只能说「可能在唱歌」**：找歌还没达标（门槛是 precision@15 ≥ 0.6、recall@10 ≥ 0.6，现在实测 0.12 / 0.38，见 `fablecut_songs` 说明）。所以不写歌名，不说「第几首」「整首」「最好的那首」，只说「可能在唱歌的段落」或「{时间} 那段」。歌名只能由主播本人填。
3. **AI 服务**：只有主播自己在设置里配了服务才用。每次发送前，确认框会显示「AI 想做这一步」和「发往：{域名}」，要让她看到发什么、发到哪里，由她点「只批准这次」或「不同意」。她没配，就不提议、也不替她去配。听写在本机跑（Paraformer），不算 AI 外发；但「用云端听写」会把声音发出去，同样要她自己选。#169 合并后，助手默认会附上「可能在唱歌的段落」和音量数字（只发数字，不发声音），发送前确认框会列出来；她不想发，就在「设置」里关掉「附上唱歌段和音量」。#170 合并后，「AI 数据说明」v3 也写明这些只是本机算出的数字、不是录音，声音本身不发；读过旧版说明的人会再看到一次。
4. **每一步都能撤销**：
   - 大改之前先存一个版本：`fablecut_versions {action:"save", name:"粗剪前"}`。界面在「项目 → 版本…」。
   - 界面撤销按 Ctrl+Z；Agent 用 `montclip_undo`；编辑器没打开时用 `fablecut_versions {action:"restore"}`。
   - 改比例**一定新建序列**：用 `fablecut_reframe {aspect:"9:16"}`，或界面「新建序列…」并勾上复制。原来的序列不动。
   - 不要在原序列上直接改画面大小，也就是不要用 `setProject {width, height}`。
5. **素材授权**：只用有授权的素材，包括录像、BGM、音效、字体，还有直播里翻唱的歌。授权不明的素材只能在本机做内部测试，不导出发布。导入外部字体和音乐时记下来源 [SC][MX]。
6. **数字一律实测**：时长、用时、条数、名次、响度，都从工具回复里读：`fablecut_get_project {compact:true}`、导出回复里的检查清单、`fablecut_normalize_audio` 的回复。没测过的数字不写。下文的「目标值」是要达到的数，不是已经测到的数。

## 2. 合格切片检查清单

一条切片要每项都过，或者明确写上「这项不适用」。

| # | 项 | 合格标准 | MontClip 里怎么做 / 怎么查 |
|---|---|---|---|
| 1 | **开头 3 秒钩子** | 前 3 秒就要出现最有看头的画面或台词：一句反转、高音、笑点、问题。前 3 秒内画面或字幕要变一次 [MX][DK][VU]。不要用片头和慢铺垫开场 [CS]。 | 选段时把最强的一句放在最前（§3 C-4 的 `keepRanges` 排序）。用 `fablecut_frame {time:0}`、`{time:1.5}`、`{time:3}` 看效果。 |
| 2 | **时长** | 竖屏短视频大多 30–90 秒；聊天/梗 15–60 秒；唱歌片段约 45 秒或一段完整的副歌 [MX][MK]。 | 「每条多长」选项。实测时长读 `fablecut_get_project {compact:true}`。 |
| 3 | **画面比例** | 竖屏 9:16、1080×1920 [CS][MX]；横屏原片保留一份。 | `fablecut_reframe {aspect:"9:16"}`（新序列）。导出预设选 `youtube-shorts` 或 `tiktok`（两者都是 1080×1920）。 |
| 4 | **字幕** | 一个停顿一屏，最多两行，每屏 1.2–3 秒 [CF][MX]。9:16 时字幕放在画面下方 10–15% 的区域，避开平台按钮和人脸 [DK][MX]。字够大，缩到手机宽还能看清 [SC]。唱歌的字幕先按歌词校准。 | 「添加字幕」或 `fablecut_captions`。「字幕大小和位置」：字号 小/中/大，位置 上面/下面。用「按歌词校准字幕」修唱词。 |
| 5 | **去空白、去口癖** | 剪掉 ≥0.4–0.5 秒的停顿，保留 0.05–0.15 秒的气口，不许剪断字 [VU][MX][CS]。删掉重复、说错又重说的地方（删前面那遍，留后面说完整的那遍）[CF]。单个自然的语气词可以留 [CF]。 | 属性面板 `Silence`、`fablecut_silence`；「查找词」、`fablecut_transcribe {find}`；「按句选段」。 |
| 6 | **卡点**（有 BGM 时） | 剪辑点落在拍上，误差 ≤3 帧 [SC]。整屏的强调效果每条最多 3 次 [SC]。 | 属性面板 `Beats`、`fablecut_beats {snap:true}`。 |
| 7 | **声音** | 整体约 **−14 LUFS**，true peak ≤ −1 dBTP [VU][CS]。人声上来时 BGM 压低 12–15 dB [VU]。 | `fablecut_normalize_audio {target:-14}`、`fablecut_auto_duck {amount:-12}`。导出时的「响度」项。 |
| 8 | **标题** | 一句话：主题加看点，不带「最/第一/唯一」这类极限词，不带引流话术，≤20 字 [MX]。唱歌切片不写歌名，除非主播自己给了名字（铁律 2）。 | 卡片名字点一下就能改，**导出的文件就用这个名字**（名字不会出现在画面里）。画面上的标题用「+ 标题」。 |
| 9 | **封面帧** | 不用开头那一帧（常常是黑的）。选表情或动作最强、画面干净的一帧 [CS][MX]，而且这一帧上没有要打码的东西，或者已经打完码。 | 播放头停在那一帧，点「导出单帧」。 |
| 10 | **结尾** | 收在一句话或一拍上，不要拖尾巴的空白 [VU][DK]。 | `fablecut_silence` 只剪尾部；拖到结尾检查。 |
| 11 | **隐私和授权** | 铁律 1、5 全部满足。 | §5 的自检。 |

## 3. 场景配方

每个配方都从导入走到导出。导出前都要做 §5 的自检。

### 通用开场（每个配方都先做）

1. **导入**：界面点「+ 导入」。Agent 用 `fablecut_import_media {path:"D:/录播/xxx.flv", link:true}`。
   - `link:true` 用硬链接导入，同盘的大录像不会复制第二份。
   - `acceptReadable:true` 只表示接受时间不确定时目前读得出的范围，**不授权**修断点或转码。
   - **FLV 断点（#130）**：不超过 0.5 秒的直接导入，只做淡标记和日志；超过 0.5 秒的要主播同意，界面由她点〔帮我转〕或〔先不转〕，Agent 得到同意后才加 `fixGaps:true`（`allowTranscode:true` 也表示同意转码）。原文件始终保留。
   - 需要转换时，H.264/AAC 和 H.264/MP3 都优先复制画面、把声音补成连续 AAC；只有编码格式不能直接进入 MP4，或复制后验收失败时才重编码。转换结果与原片时长差要在 0.1 秒内、声画差要在 40 ms 内，否则报 `FLV_FIX_UNVERIFIED`，不交付。损坏字节或解码时间倒退会拒绝；声画逐渐漂移超过 40 ms 只报告，不能声称已经校正。
   - 导入后如果提示「没录完整…读不出有多长，现在还剪不了」（文件会标上「不能剪」），或者文件上有「没录完整，拖动可能会慢」的小记号，先去走配方 E 修好，再继续往下剪。
   - 像素不是方的录像，`width × height` 按实际显示尺寸给；文件里存的原始尺寸另记在 `storedWidth × storedHeight`，只有两者不同时才有这两个字段（#159）。老项目会在下次读状态时改正。算 Reframe 和裁切位置时用显示尺寸，不要拿原始尺寸混算。
   - 录像有好几条音轨（例如 OBS 把麦克风、游戏和音乐分开录）时，先走配方 G，再找到可能在唱歌的段落、听写、算响度或剪停顿。
2. **弹幕（可选）**：点「文稿」页里的「导入弹幕…」，或调 `fablecut_danmaku {path:"….xml", mediaId}`。
   - 支持录播姬和 B 站的 XML。
   - 用户名和用户 id **不会存下来**，礼物和醒目留言只计数。
3. **存版本**：`fablecut_versions {action:"save", name:"导入后"}`。
4. **看一眼素材**：`fablecut_frame {path:"/media/…", frames:24}` 出一张缩略图拼图。没有视觉能力的模型加 `text:true`。在这一步记下礼物栏、榜单、连麦窗口、昵称在画面里的**位置**（打码要用）。

### 配方 A：直播唱歌切片

1. 先做通用开场。
2. 在「文稿」页点「✨ 自动出切片」：
   - 第 1 步「选录像」：勾上这一场。只有一场录像时会自动勾上。
   - 「这场主要在干什么？」选「唱歌」，提示语是「会找可能在唱歌的段落，每段单独出一条」。
   - 「最多出几条」可选 3 / 5 / 8 / 12。
   - 「每条多长」：
     - 发竖屏动态，选「只要最好听的一部分（约 45 秒）」，它会切声音最响的那部分。
     - 要完整的段落，选「唱歌的段落整段出」。
   - 想要字幕，就勾「加字幕（在这台电脑上听写，声音不发出去）」。
   - 点「开始找高光」。
   - Agent 版：`fablecut_songs {mediaIds:["m_xxx"]}`，结果存在 `project.songs`。中途停了，下次会从停下的地方接着读。main 上这次扫描可以带 `wait_ms` 上限等待；得到 `taskId` 后用 `{taskId}` 取结果，改动带 `idempotency_key` 防重。
3. 第 3 步「看一遍」，每张卡逐条过：
   - 卡片名是「{时间} 那段」，标签是「可能在唱歌」。两端标「估的」或「比较可能」，**两端都要听**：「▶ 听开头」「▶ 听结尾」。不准就点「调一下」挪「← 早 / 晚 →」，挪过的会标「你调过」。
   - 用「▶ 试看」从头看一遍。不是唱歌的点「这段不是唱歌」，不要的点「不要这条」，漏掉的点「＋ 补一段」。
   - 字幕有错字：点卡片上的「如果这段是唱歌，可以按歌词校准字幕」，粘贴**主播提供**的歌词，一行一句，再点「对齐」。
     - 「可能不对」那几行逐行确认，然后点「应用勾选的」。
     - 不要自己去网上找歌词填。
     - **Agent 两步歌词对齐（#164）**：先 `fablecut_lyrics {lyrics:"…", clipIds:[…], from:<起>, to:<止>}`，在本机听写并对齐，只出方案，不改项目；回复给主播看方案时只引几行。至少对上 20% 的行、且至少 2 行才是 `OK`（只有 1 行时那 1 行对上即可）；`TOO_FEW` / `NO_VOCALS` / `NO_LYRICS` / `ASR_UNAVAILABLE` 都不能应用。这个 0.2 门槛只用模拟听写结果测过，真实人声还没实测，不能把它说成识别准确率。
     - 主播看过方案后再调 `fablecut_lyrics_apply {proposalId}`。必须开着编辑器，每种助手模式都由她在确认框点〔放到时间线上〕才执行；〔先不用〕就什么都不改。执行会新建一条字幕轨，原字幕不动；对不上的行是灰色 `disabled`，不进预览和导出，留她自己拖、自己打开。Ctrl+Z 一步撤掉字幕（空轨会留下）；方案之后相关片段改过就拒绝。工具不识别歌名，仍只说「可能在唱歌」。
   - 卡片名点一下可以改，导出的文件就叫这个名字。不填歌名，除非主播本人说了歌名。
4. 要细剪（加钩子、竖屏、打码）就点「放到时间线上（n 条）」；只要原样横屏输出，就点「直接导出这 n 条」。
5. 细剪：
   - 钩子 [检查清单 #1]：把这段里最高的一句或最炸的反应，复制一段放到最前面（见配方 C 第 4 步的 `keepRanges` 用法）。
   - 竖屏：走配方 D。
   - 字幕位置：选中字幕，在「字幕大小和位置」里设字号「大」、位置「下面」。
6. 声音：
   - `fablecut_normalize_audio {clipIds:[…], mode:"lufs", target:-14}`，或在属性面板 `Audio / Time` → `Normalize` 选 −14 LUFS → `Apply`。
   - 唱歌一般不要降噪；底噪确实明显时，`Noise` 选 `Light`。
7. **打码**：照 §4 做（礼物栏、榜单、连麦窗口、昵称弹窗）。
8. 自检 §5 → 导出：
   - 界面：「导出」→「预设」选 YouTube Shorts 或 TikTok →「响度」选 −14 →「导出」→ 在「导出队列」里点「保存」。桌面版完成后还可以点〔在文件夹里显示〕找到文件（#138）。
   - Agent：`fablecut_export {preset:"youtube-shorts", delivery:{audio:{loudness:-14, truePeak:-1}}, range:"in-out"}`。
9. 向主播汇报时只说「可能在唱歌的段落」和实测时长，不说「第几首」。

### 配方 B：聊天、梗的高光

1. 先做通用开场，有弹幕就一定导入（弹幕密度是高光的依据之一）。
2. 「✨ 自动出切片」→「这场主要在干什么？」选「聊天」，打游戏选「打游戏」，一起看选「一起看」，或者选「让它自己看」→「每条多长」选「30 秒–1 分钟」→「开始找高光」。
   - 也可以先在「文稿」页点「高光候选」看候选。这一步只在本机判断，不调用 AI。
   - 候选给出的理由会写成「比平时响」「有一下特别响」这样。
   - Agent 版（得到一条混剪）：`fablecut_highlights {duration:30, aspect:"9:16"}`。它会在**新序列**里拼出 30 秒，原时间线不动。每个时刻都会写出来源和入选理由。main 上可以带 `wait_ms` 上限等待；改动带 `idempotency_key`，同钥匙重试不会再拼一份。
3. 「看一遍」：每条都要「▶ 试看」，确认梗是完整的：要有铺垫、笑点和反应。只截到笑点、没有后面的反应，算没过 [VU]。不完整就「调一下」，把结尾往后挪。
4. 「放到时间线上」后做细剪：
   - 去空白：选中片段，在属性面板 `Silence` 设 `Below` −40 dB（房间吵就调到 −30）、`At least` 0.5 s、`Keep` 0.1 s → 点 `Find`，先看时间线上的标记 → 点 `Cut N`。
   - Agent 版：先 `fablecut_silence {clipIds:[…], threshold:-40, minSilence:0.5, padding:0.1}` 只报告，看过再加 `cut:true`。它会先自动存一个版本。
   - 去掉念出观众名字的句子：见 §5.2。
5. 字幕：「文稿」→「听写」→ 选样式（短视频用 `highlight` 或 `pop`）→「添加字幕」。Agent 版：`fablecut_captions {style:"highlight"}`。**字幕最后加**：加完字幕再剪，字幕不会跟着重新对齐。
6. 竖屏走配方 D → 打码走 §4 → 自检 §5 → 导出（同配方 A 第 8 步）。

### 配方 C：口播粗剪（去口癖、去重说、去停顿）

1. 先做通用开场 → `fablecut_versions {action:"save", name:"粗剪前"}`。
2. 听写：「文稿」→「听写」，Agent 用 `fablecut_transcribe {}`。
   - main 上这次听写可以带 `wait_ms`（0–15000 毫秒，默认 6000）上限等待；回复的 `taskId` 留下来，之后用 `fablecut_transcribe {taskId}` 取回结果，不要连着轮询。`wait_ms` 只限你等多久，不会停掉后台听写。
   - 没听完时回复会明说「没听完」，已经听完的段落会先存到本机 `analysis/transcripts/` 下（提示里给的是相对路径，不带本机绝对路径），取消或超时不丢已完成的部分；没有任何完成段落时只说保存位置，不会假装已经有文件。
   - 没装听写模型时会提示「还没装听写模型（约 240 MB），现在还不能把说的话转成文字。装好以后再试一次。」没有听写程序时会提示「这台电脑上的 MontClip 还没有听写程序，现在还不能把说的话转成文字。剪辑、导出照常能用。」按提示去「设置 › 听写」，让主播自己点下载或导入；Agent 不要替她去下载。
   - 长录像（>10 分钟）且时间线上的片段只覆盖全片不到一半时，main 只听写片段用到的窗口（每段前后多取 1.5 秒）；增量补读不会再整段重听。`mediaIds` 整文件听写不适用这条。时长未知的录像（修好前读不出有多长的那种）也只听写片段窗口，不会整段跑（#231，MC-11）。
3. 去重说、去说错（删前面那遍，留后面那遍 [CF]）：
   - 逐句读文稿，找重复、半句、说错重说的地方。
   - 「文稿」→「按句选段」：勾上要留的句子 →「试听选段」→「保留选段」，一步就能撤销。
   - Agent 版：`fablecut_captions {keepIds:[…], baseRevision:<当前修订号>}`。先把选了哪些、中间空出哪些拿给主播看，她同意了再应用。这类改动带 `idempotency_key`；同一把钥匙重试拿回原来的结果，不会因为重试把片段再删一遍。
4. 加开头钩子 [检查清单 #1]：`fablecut_captions {keepRanges:[{from:钩子起, to:钩子止},{from:正文起, to:正文止}], baseRevision}`。
   - 区间按你给的顺序拼接，所以把最强的一句（3 秒左右）排在最前就行。
   - 被拒绝的话（比如区间重叠），就把钩子那句从正文里去掉再试，或者手动 `insert`。
5. 去口癖：「查找词」里输入「呃」，按 Enter 一处处跳过去听 → 确认都该删，再点「剪切」（或「剪掉 {n} 处」）。
   - Agent 版：`fablecut_transcribe {find:["呃","嗯"]}` 先只报告位置，挑过之后，只对确认的词加 `cut:true`。
   - 有意义的「嗯」（比如表示认同）要留着 [CF]。
6. 去停顿：属性面板 `Silence`（或 `fablecut_silence`），`minSilence` 0.4–0.5、`padding` 0.08–0.15 [VU][MX]。一次剪掉的总时长最好不超过原片的 20%；超过就先问主播 [MX]。
   - 有 BGM 时，先在轨道锁上锁住 BGM 轨，BGM 就会一直放下去。
7. 剪完再加字幕：「添加字幕」，口播用 `subtitle` 样式。改字号和位置用「字幕大小和位置」。
8. 声音：
   - 背景有嗡嗡声或嘶声：`fablecut_denoise {clipIds:[…], amount:"light"}`，属性面板 `Noise` 也能选（`Light` / `Medium` / `Strong`）。`medium` / `strong` 可能让人声发闷，要先听。
   - 口播响度可以用 −16 LUFS [CS][MX]；发短视频平台用 −14。
   - 有 BGM：`fablecut_auto_duck {clipIds:[BGM], amount:-12}`。
9. 自检 §5 → 导出。要出横屏用 `preset:"youtube"`，要出竖屏先走配方 D。

### 配方 D：竖屏短视频（任何横屏剪好的序列 → 9:16）

1. 先存版本 → `fablecut_reframe {aspect:"9:16"}`。
   - 它会**新建一个 9:16 的序列**（1920×1080 变成 1080×1920）并打开，原横屏序列不动。
   - 每秒取 5 帧找主体，还会补读**片段的最后一帧**（#176），生成跟着主体走的 x 关键帧。`smooth` 是 0…1（默认 0.5），越大镜头越稳。老项目已经算好的关键帧不会自动重算；要用上末帧修复，就重新执行一次 Reframe。
   - 界面：时间线工具栏 → 序列菜单 →「新建序列…」→ `Canvas` 选 `9:16 · Reel 1080×1920` → 勾 `Start from a copy of …` 和 `Follow the subject in each shot` → `Create`。
   - **桌面助手也能做（#175）**：直接跟它说「改成竖屏」；它只认 9:16 / 1:1 / 4:5，且改比例不能塞进多步计划，要单独说一句。每次都会先问，「自动」和「全自动」也一样；确认后有进度和〔取消〕。取消、读画面失败或中途项目被改过，都不会新建序列。撤销一次会回到原序列并删掉新序列，这一步没有重做。
   - **Cindy 插件版**：没有 #175 的桌面助手流程（AI 操作在 Cindy 对话里说）；#176 的末帧修复已在插件引擎里，但老项目已算好的关键帧不会自动重算，要用上就重新执行一次 Reframe。用 `fablecut_reframe` 做完后，尤其要检查每个镜头的结尾。
2. 回复里会列出被跳过的标题、画中画、手动摆过位置的片段和锁住的片段，逐个用 `fablecut_frame {time}` 在新画面里看。主体跟丢的镜头，在属性面板 `Reframe` 里点 `Follow subject` 重做，或者手动改 x 关键帧。结尾也要看，不能只检查前半段。
3. 字幕重新摆：在「字幕大小和位置」里选「下面」。然后在画面下方 10–15% 的区域里，用 `fablecut_frame {time}` 抽几帧，确认字幕没被平台按钮和人脸挡住 [DK][MX]。
4. **最后打码**（§4）。Reframe 会改镜头位置，所以打码要放在 reframe **之后**做，打完逐帧检查。
5. 卡点（有 BGM 时）：BGM 片段在属性面板 `Beats` 里点 `Find beats` → `Snap cuts`；要按拍重排就用 `Re-cut` 每 2 拍一刀。
   - Agent 版：`fablecut_beats {clipId:"BGM", snap:true}`，或 `{retime:{every:2}}`。
   - 只用有授权的 BGM（铁律 5）。
6. 自检 §5 → 导出 `preset:"youtube-shorts"`（1080×1920，≤3 分钟）或 `preset:"tiktok"`，加 `delivery:{audio:{loudness:-14}}`。

### 配方 E：录像读不出时长 / 拖不动——「帮我修好」一键修复（#157）

录像中途停掉（比如录屏崩了）会出现两种情况，都有同一个修法：

| 表现 | 界面上看到 |
|---|---|
| 读不出时长 | 素材上写「这个视频没录完整…现在还剪不了」，还有〔帮我修好〕按钮；拖不上时间线 |
| 能剪但拖动慢 | 素材上一个小记号「◔」：「没录完整，拖动可能会慢」 |

修法（视频专用；音频文件没有这个按钮）：

1. 界面：在素材上点〔帮我修好〕（或右键 →「帮我修好…」）。Agent：`fablecut_repair_media {mediaId:"m_xxx"}`。
   - 它是后台任务：立刻返回一个任务号，之后用 `{job:"r_…"}` 查进度，`{cancel:"r_…"}` 取消（取消就什么都不改）。同一个文件再调一次只会并入正在跑的那个任务。
   - 先尝试快速重封装（不重编码）；不行才用本机 FFmpeg 的 libx264 或内置编码器重编码。重编码做不了（本机 FFmpeg 不行）会拒绝，原文件不动。
2. 修好后：在原文件旁边写出一个新的 MP4（`原文件名.repaired.mp4`），时间线上所有用到它的片段自动换成新文件、位置不变；**原文件不动**，而且修之前自动存了一个版本，按 Ctrl+Z（或 `montclip_undo`）可以换回来。
   - Agent 查任务结果时，用返回的**新** `mediaId` 和 `result.duration` 往下剪。
3. 修完仍读不出的（比如 MP4 索引没写完的）：会明说「这种修不了，请换一个完整的文件」，原文件没有改动。

**注意（Cindy 插件版）**：插件引擎已含 #157，`fablecut_repair_media` 可用（以 `list_tools` 实际列出为准）。

### 配方 F：录像被移走或删掉——先找回来（#137、#193）

素材上写「找不到」时，剪辑还在，不要重剪，也不要拿同名的另一场录像直接顶替。

1. 在素材库顶上的提示条点〔找到它…〕；有好几个时点〔一个个找回来…〕。也可以右键素材 →「重新链接…」。
2. main 只会把**同名、同大小、而且只有一个候选**的文件自动接上，最后提示「已经自动找回 {m} 个」。名字相近、同名但大小不同，或者有多个候选，都要在「找回录像」里人工选；对话框只显示文件名，不显示完整路径。
3. 剩下的文件用〔选文件…〕一个个选，或〔选文件夹…〕按文件名配对，再点〔找回〕/〔找回 {n} 个〕。找回后时间线上的位置和剪辑点不变。
4. 导出时仍有素材找不到，会提醒这几段导出后显示「找不到」、没有声音：点〔先找回来…〕回去处理；〔照样导出〕会真的留下这些无画面、无声的段落，交付前不要拿它当成片。
5. **Cindy 插件版**的引擎已含 #137 / #193，以上提示和自动找回限制同样适用。

### 配方 G：多音轨录像——先选主播的声音（#177）

OBS 可以把麦克风、游戏和音乐各录一条轨。main 导入多音轨 MP4 时保留每条音轨，默认读第 1 轨（工具里的 `track:0`），OBS 这一轨通常是混好的全部声音。**只有主播说她的声音在别的轨上时才换**，不要为了「提纯人声」自己猜一轨。

1. 界面在素材上点音轨标记，或右键素材 →〔选音轨…〕，在「主播的声音在哪条轨」里逐条点〔试听〕，再选主播确认的那条。Agent：
   - `fablecut_audio_track {mediaId:"m_xxx"}` 列出音轨编号、声道数和 OBS 写的名字。
   - `{mediaId, listen:<从第几秒开始>}` 从该位置给每条轨各取 6 秒，放到 `analysis/listen/` 给主播听。
   - 她确认后用 `{mediaId, track:<编号>}` 选择。工具编号从 0 开始，界面从 1 开始：工具的 `track:0` 就是界面「第 1 轨」，跟主播说编号时别差一轨。
2. 找歌、响度分析、听写和字幕、节拍、静音、高光都改听选中的轨；**导出声音、响度归一和自动压低音量仍用 `track:0`**，所以选麦克风轨不会把游戏和音乐从成片里删掉。
3. 选择本身是一步撤销。换轨后，旧轨找到的唱歌段落会被清掉，要重新跑 `fablecut_songs` 和 `fablecut_transcribe`，再做后面的分析；不要沿用旧轨的字幕或数字。
4. **Cindy 插件版**的引擎已含 #177，`fablecut_audio_track` 可用（以 `list_tools` 实际列出为准），换轨后同样要重新跑找歌和听写。

## 4. 打码（main 上的做法）

**本节是 Agent 配方修正，不是已验收的全按钮打码流程。** 普通「添加形状」按钮不是隐私覆盖预设。
手动精确框选、运动跟随、独立修改填色后的撤销，以及 Cindy 实窗操作均未验收。

一步打码的工具 `fablecut_blur_region` 所在 PR #163 已关闭且未合并，main 没有这个工具，现在不能用。其模糊和马赛克强度也不能当作隐私保证。

**用不透明色块完整盖住敏感内容，并留出边缘余量。** 色块必须在所有包含敏感内容的图层上方，覆盖完整时段。

```
fablecut_patch_project {ops:[{op:"addClip", clip:{kind:"shape", track:"V3", start:<起>, duration:<长>,
  props:{opacity:1, blend:"normal", shapes:[{type:"rect", x:<中心x像素>, y:<中心y像素>, w:<宽像素>, h:<高像素>, radius:0, fill:"#000000"}]}}}]}
```

形状的 x/y 是相对画布中心的像素坐标，不是遮罩的 0…1 比例。比如画布 320×180，
`x:-112, y:-69, w:96, h:42` 覆盖左上角 x=0…96、y=0…42。V3 只是示例，要确认没有更高的轨道再次显示敏感内容。
矩形设 `radius:0`，保留直角硬边；片段透明度为 1，混合为 normal，填色完全不透明。
不要给色块加模糊、羽化或淡入淡出。不能直接沿用形状按钮的默认轨道、4 秒时长、大小或圆角：
必须另行核对最高可见图层、整个敏感时段、完整区域及边缘余量。手动界面的这些设置步骤尚未验收，
不能据本节宣称已完成按钮操作验证。

**会动的东西**：用位置和缩放关键帧让色块跟随，或者用足够大的色块覆盖完整运动范围。
裁切、推拉或 Reframe 之后重新调整覆盖范围；追踪分数再高，也不能代替逐帧检查。

**撤回旧模糊配方作为隐私推荐。** 清晰底图上叠模糊副本，即使遮罩没有羽化，
也可能因模糊后的半透明边缘透出底图；模糊更强不一定更安全。调节层、叠第二层、
马赛克和给底层挖洞都不能未经验证就当作安全替代。艺术模糊仍可使用，但不能承诺隐私。

打码完一律做 §5.1 的逐帧检查。合成验证及适用范围见 `reference/privacy-cover.md`；
这不等于真实素材已验收。

## 5. 导出前自检（每条都做，做完才导出）

**导出前的 FFmpeg / 编码器检查（#125、#146）**：main 启动时按「内置 → 系统 PATH → 主播选过的位置」找 FFmpeg 和 ffprobe。找不到、缺 ffprobe 或版本太旧时，导出先停下并说明原因；只有缺 H.264 时，简单模式关掉整个〔导出〕，高级模式只关掉 MP4（H.264）选项，其他格式仍可导出。顶栏下方的卡片会按系统给〔重新检测〕、Windows 的〔选择 ffmpeg.exe〕或 Linux 的〔我装在别处了，手动选择〕；浏览器没有文件对话框时，卡片给「FFmpeg 放在哪（完整路径）」输入框。它不会自动下载，也不会启动服务器可写目录里的程序。

有内置版时，外部 FFmpeg 只负责 H.264 编码，预览、解码、探测和分析仍用内置版；完全没有内置版时才让外部版承担全部工作，此时要 FFmpeg ≥6.0，并实际通过响度和找歌滤镜检查。这些检查不能代替下面的成片自检。Cindy 插件引擎已含 #146 的检测逻辑；插件自己的 FFmpeg 下载安装与主播自选 FFmpeg 仍按 §0 的插件说明做，两边界面看到哪条照哪条做。

### 5.1 打码逐帧检查

- **所有含敏感内容的镜头**：预览和最终成片都要看每一帧，包括固定位置、缩放、位移和 Reframe 的镜头。
  - 界面：播放头放到这段开头，按「→」一帧一帧走到结尾（Shift+→ 是 1 秒，不算逐帧）。
  - Agent：从这段的起点开始，每次加 1/fps 秒，调 `fablecut_frame {time}`，逐帧看蒙版有没有露出昵称、礼物或榜单。
- **导出后对成片再查一遍**：按成片实际帧率逐帧解码并检查，确认帧数和时间范围完整。缩略图拼图是抽样，不能仅凭 N 和时间窗口就认定没有漏帧。
- 检查剪辑点前后、覆盖块边缘和整个敏感时段；发现一帧露出就扩大或调整色块，再导出重查。

### 5.2 原声里有没有念出观众名字

- 从头到尾听一遍原声，这一步不能用读文稿代替 [CF]。
- 再用 `fablecut_transcribe {find:[<主播提供的常客昵称>…]}` 查一遍。文稿可能听错名字，所以搜不到不代表没有。
- 念到名字的地方，用 `fablecut_transcribe {find, cut:true}` 把那句剪掉；要保留画面的话，就在那一段把音量拉到 0（先 `split`，再 `updateClip` 设 volume）。

### 5.3 响度约 −14 LUFS

- 导出前跑一次 `fablecut_normalize_audio {target:-14}`，或者在导出的 `delivery.audio.loudness` 里设 −14、`truePeak` 设 −1。
- 导出完成回复会把成片的 loudness 和 true peak 跟目标值对一遍。Cindy 插件里先用 `{job}` 查到完成再读；`montclip_export` 要到 `done` 且文件到位才算完成，不能把 `running` 或重载后的 `exported` 当成已交付。**写进汇报的数字就用完成回复里读到的**。

### 5.4 导出后的黑屏、无声、单声道自检

- 先读导出回复里的检查清单（尺寸、帧率、帧数、编码、时长、响度、true peak、文件大小）。哪一项跟要求不一样，就不算完成。
- **工具报错的统一脱敏（#240）**：main 上 `fablecut_*` 的报错和警告（包括正常回复里带的警告）都过同一条脱敏边界，本机绝对路径、密钥、令牌不进给 Agent 的回复和任务回执；旧的完成回执会先在本机改写干净再返回，改写不会重跑那次的改动。回执里数据目录外的路径会被省略或留空，不要拿它当可用文件。插件引擎已含这批脱敏；插件里看到报错仍按 §5.2 和 §5.4 自己核对，不要把路径再原样转给主播。
- **失败条数和问题信息（#129）**：结果会写清几条导出好了、几条没导出来；失败或取消的队列条目可以点〔重试这条〕。〔复制问题信息〕复制的是脱敏日志，去掉本机用户目录、密钥和令牌、观众昵称和 uid；原始错误只进日志。复制问题信息不是成片合格证明，重试后仍要重新验收。
- **桌面版找文件（#138）**：导出队列里已完成的条目有〔在文件夹里显示〕；素材库右键也有这项。导出队列的按钮只在桌面版出现；素材右键这项在浏览器版会写「只在桌面版里能用」。素材不在时先「重新链接」，文件被移走会提示「文件已经不在了」。已「保存」到别处的导出，在这次桌面应用开着期间也能定位到保存后的文件。
- **自定义 JPEG / ProRes 422 导出**：main 上（#190）会按项目选定的帧数截住声音，修掉末尾 PCM 尾包丢失和音频过滤链映射错误；预设里无法保证照做的自定义声音或滤镜设置会直接拒绝，不生成文件。这条只适用于带明确 `frames` 的这条导出路径，其他预设不变。插件引擎已含这项修复；ProRes 导出后仍要核对项目时长，并听完结尾。
- **失败 / 取消 / 超时的导出**：main 上（#178）会立刻停掉 ffmpeg、删掉半成品 `.part` 文件——导出回复说「完成」才算完成，文件真正到位才算。**插件引擎已含 #178**；插件外壳（#9）还会在 worker 停止时调用引擎 shutdown，清掉仍在跑的 ffmpeg。看到 failed/cancelled 仍按提示重来，别把半成品当成片。
- **整片黑屏 / 无声自动兜底（#161）**：main 会在导出后取 8 个时刻，对比成片和时间线素材；整片黑屏而素材有画面，或整片无声而素材有声音时，导出标失败，分别报 `EXPORT_BLANK_PICTURE`、`EXPORT_BLANK_SOUND` 或 `EXPORT_BLANK_BOTH`，文件先别用。时间戳不从 0 开始的录像也修了声画定位。这个兜底不是逐帧、逐段验收：画面检查是抽样，局部黑屏、局部无声仍要靠下面的检查。插件引擎已含 #161。
- **逐段声音核对（#231，MC-14 / MC-15 / MC-11；#238 / #245 后续）**：main 导出后除整片兜底外，还会逐段核对每段有画面的片段和每条单独的声音（音乐、配音）。三种结果分得很清：
  - **真读不出**（ffmpeg 失败、没解出声音等）：导出停下、**不生成文件**，提示「第 {n} 段（时间线 {time} 处）的声音没读出来，这次导出已停下，没有生成文件。原片没有改动。」（多条一次列完）；单独的声音没有段号，按时间线位置说「时间线 {time} 处的声音没读出来…」。
  - **文件里本来无声**：不会误判成读不出，而是在报告里提示「第 {n} 段（时间线 {time} 处）是无声的，请确认是不是你想要的。」。
  - **核对超时**（`EXPORT_CLIP_UNCHECKED`）：导出核对读某段文件等了默认 20 秒还没读完（典型的例子是碎片化的长 MP4 冷盘开文件就要二十几秒），**文件保留**，报告里警告「第 {n} 段（时间线 {time} 处）在成片里没有声音，软件没能确认原片是不是也没有。成片已经导出，请先自己听一下这一段，再决定要不要发。」——「没能确认」既不是导出失败，也不能当成核对通过，要让主播自己听那一段。
  - 做导出的页面意外关掉时提示「导出时出了意外，这次导出已停下，没有生成文件。原片没有改动。可以直接重新导出…」；失败任务的记录里会带上原因代码（`EXPORT_AUDIO_FAILED`、`EXPORT_NO_H264` 等），不是只有一句英文。
  - **插件引擎已含这批**（#231 / #238）；但「没能确认」不是核对通过，局部问题仍靠本节的人工自检。
- **黑屏**：即使 main 的自动兜底通过，也要用 `fablecut_frame {path:<导出文件>, frames:24, text:true}` 看每格亮度。连续好几格接近全黑，就是有问题，不要等到 0.5 秒以上的黑段才算 [MX]。开头一格和结尾一格一定要看。
- **无声**：回复里的 loudness 远低于目标（接近无声）就是失败。再从头到尾听一遍，3 秒以上的无声段要找到原因 [MX]。插件版导出长录像时尤其要查（§0）。
- **单声道 / 单耳声音（#179、#183）**：main 新增的单声道录音会居中。旧项目里有声音只在左耳时，打开项目会问「要改成两边都有吗？」：主播点〔改成两边都有〕才居中，一步撤销；点〔不用〕就保留。Agent 在 `fablecut_status` 看到这项警告时也要先问她，不要默默改。导出后 main 直接测成片左右声道：较响的一边高于 −60 dB、两边差超过 20 dB 才提醒；短于 2 秒、时长未知或全静音不报，手动 pan 或 pan 关键帧也不报。警告会保留文件，找到可居中的单声道原因时给〔改成两边都有〕，改完重新导出。**插件引擎已含 #179 / #183**；但自动检查有阈值，单声道素材仍要双耳各听一下，只在一边有声就先告诉主播，她同意后再改。
- 时长：要和 `fablecut_get_project {compact:true}` 里的序列时长对得上。

## 6. MontClip 做不到的步骤，以及怎么手动替代

| 做不到 | 手动替代 |
|---|---|
| 一步打码（`fablecut_blur_region`） | §4：不透明色块完整覆盖，运动时加关键帧，再逐帧检查。 |
| 可靠的唱歌段落起止、歌名、「第几首」 | 只当「可能在唱歌」用，两端都要人听着调。歌名只由主播给。 |
| 局部黑屏、局部静音的完整自动验收 | main 和插件引擎的 #161 都只兜底整片黑屏 / 无声（抽样），#231 只逐段核对读不出的声音；局部黑屏、局部无声仍要靠 §5.4 的抽帧和从头到尾听一遍。 |
| 自动生成钩子、标题、文案 [MX] | 人挑最强的一句，用 `keepRanges` 放到最前。标题人写（按检查清单 #8）。 |
| 封面图模板、封面 A/B [MX] | 「导出单帧」出一帧，套字要用别的工具。 |
| 安全区参考线（平台按钮位置）[MX] | 用 `fablecut_frame` 抽帧，按画面下方 10–15% 区域的规则用眼睛检查。 |
| 字幕每秒字数、闪屏检查 [MX] | 加完字幕后，读 `fablecut_get_project {compact:true}`，挑出短于 0.5 秒或一屏字太多的字幕，手动合并。 |
| 中文按字精确剪（README 说中文目前只有句级时间） | 用「按句选段」按句子剪。要细到字时，在时间线上按「←/→」逐帧找切点，再用 `split` 切开。 |
| AI 生成画面、配音、BGM 库、去原字幕、人声分离 [MK][MX] | 不在 MontClip 里做。用有授权的外部素材，「+ 导入」进来。 |
| AI 人像抠像 | 只在浏览器版用：每次重开 MontClip 后第一次启用都要联网下载 MediaPipe 资产，弹窗会先问主播本人（「要联网下载 AI 抠像吗？」，会写明连接 jsDelivr、只下载不上传、抠像在本机算）；她点「联网下载」才下载，Esc / 「先不用」就不启用。资产按钉死版本逐字节校验，校验失败不能用。桌面版没有这个入口（提示可改用按颜色抠像）。导出若包含 AI 抠像片段，「边播边录」会被拒绝，预览/导出的蒙版缺失也会拒绝；Agent 不能代答同意。它抠的是人像，不是观众昵称/礼物打码。 |
| 导出剪映草稿、EDL、FCPXML、OTIO [MX][SC] | 没有。只能导出成片和 SRT/VTT 字幕（`fablecut_captions {export:"srt"}`）。 |
| 去掉画面里已有的观众昵称弹幕层 | 只能盖住（§4），不能擦除。 |
| 导出后自动发到平台 | 没有。在「导出队列」里「保存」后，人工上传；桌面版可用〔在文件夹里显示〕找到文件。 |
